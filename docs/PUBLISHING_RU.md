# Публикация обновления

## 1. Подготовка

Перед публикацией должны быть известны:

- тип: `ota` или `core`;
- версия;
- аппаратная цель;
- полный путь к проверенному файлу;
- результаты сборки и стендовых проверок;
- явное подтверждение владельца: обновление согласовано.

Не публикуйте тестовую или неподтверждённую сборку.

## 2. Контрольные данные

PowerShell:

```powershell
Get-Item -LiteralPath '.\firmware.bin' | Select-Object Name,Length
Get-FileHash -Algorithm SHA256 -LiteralPath '.\firmware.bin'
```

SHA-256 записывается строчными шестнадцатеричными символами. Размер указывается точно в байтах.

## 3. Новый GitHub Release

Для каждой новой публикации создайте новый Release и уникальный тег, например:

```text
updates-2026.09.05-1
```

Не заменяйте файл в старом Release. Имена файлов должны включать версию и аппаратную цель.

Сначала загрузите бинарные файлы, затем подготовьте `lanza-ds-updates.json` по шаблону. Для ссылок используйте форму:

```text
https://github.com/t2Engineer/2t-engineer-updates/releases/latest/download/ИМЯ_ФАЙЛА
```

Манифест загружается в Assets последним. Его имя всегда:

```text
lanza-ds-updates.json
```

## 4. Разрешённые цели

| Тип | target | Файл |
|---|---|---|
| ESP32 16 МБ | `16MB` | `.bin` |
| ESP32 START 4 МБ | `START-4MB` | `.bin` |
| Ядро MOTO2.x | `MOTO2` | `.bin` или `.crp` |
| Ядро старой линии 4.x | `LEGACY4` | `.bin` или `.crp` |

`ANY` допускается форматом только для заведомо универсального файла и требует отдельного явного согласования.

## 5. Проверка после публикации

1. Откройте постоянную ссылку манифеста и убедитесь, что возвращается JSON, а не HTML.
2. Откройте каждую ссылку `url` из манифеста.
3. Сверьте имя, размер и SHA-256 скачанного файла.
4. В приложении **2T Инженер** нажмите «Проверить обновления».
5. Проверьте, что несовместимая аппаратная цель не предлагается к установке.
6. Зафиксируйте версию, SHA-256 и результаты проверки в задаче соответствующей прошивки.

## 6. Ограничения приложения

- `schema_version` сейчас равна `1`;
- от 1 до 16 записей `updates`;
- размер каждого файла: от 1024 до 4194304 байт;
- `release_name` — до 120 символов;
- `release_notes` — до 1200 символов;
- `notes` — до 600 символов;
- токены, логины и пароли в URL запрещены.
